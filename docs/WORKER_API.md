# Worker API v1

The only server code of Research Design: a Cloudflare Worker (`worker/`) on the lab's shared R2 bucket, under
the prefix `researchdesign/`. It checks who is calling, keeps projects and their documents, and is the place
where a plan becomes frozen. The LLM proxy and the usage ledger are slice S4 and are not described here.

## Rules for every request

- **Auth.** `Authorization: Bearer <Firebase ID token>`. The token is verified by `worker/src/auth.ts`
  (Google's signature, this Firebase project, a verified Google account, domain `hyperdatalab.org`).
  No or bad token: `401`. A good token from another domain: `403`.
- **CORS.** Only origins in `ALLOWED_ORIGINS` get `Access-Control-Allow-Origin`. `OPTIONS` answers the
  preflight without auth. Allowed methods: `GET, POST, PUT, PATCH, OPTIONS`; allowed headers:
  `Authorization, Content-Type, If-Match`; exposed header: `ETag`.
- **Bodies** are JSON, at most 2 MiB for a document and 8 MiB for an item (`413` beyond). Malformed JSON or a wrong shape: `400`.
- **Errors** are `{ "error": "<code>", "message": "<English sentence>" }` with the status. Codes:
  `unauthenticated`, `forbidden`, `not_found`, `bad_request`, `too_large`, `conflict`, `precondition_failed`,
  `plan_invalid`, `method_not_allowed`, `internal`. An unexpected failure is `500 internal` with the usual CORS
  headers and no detail of the failure.
- **Membership.** A project is visible only to its members. A caller who is not a member gets `404`, the same
  answer as for a project that does not exist, so ids cannot be probed.
- **The bucket interface** (`Bucket` in `worker/src/app.ts`) is the part of R2 the Worker uses: `get` (text and
  `httpEtag`), `put` (with optional `onlyIf: { etagMatches }`, resolving to `null` when R2 refuses), `delete`,
  `list` (prefix, cursor). Tests use an in-memory implementation of it.
- **Ids.** Project ids are generated by the Worker: 16 lowercase hex characters from `crypto.getRandomValues`.
  Any id or name taken from the URL is checked against its pattern before it is used in a key.
- Time comes from `deps.now()`, as ISO UTC strings ending in `Z`.

## Storage layout

```
researchdesign/projects/<projectId>/project.json          Project
researchdesign/projects/<projectId>/docs/<kind>.json      a working document, opaque JSON
researchdesign/projects/<projectId>/items/<collection>/<itemKey>.json   one item of a collection, opaque JSON
researchdesign/projects/<projectId>/plans/<version>.json  a frozen plan, written once
researchdesign/members/<email>/<projectId>                empty marker: this member belongs to this project
```

The member markers make "my projects" one `list` call. They are written and removed together with the
project's member list; `project.json` stays the source of truth, and a marker whose project does not list the
member is ignored. Write order: markers for new members first, then `project.json`, then delete the markers of
removed members, so a write that fails half-way never hides a project from one of its members. Every `list`
follows the cursor until `truncated` is false.

## Objects

```ts
interface Project {
  id: string;
  title: string; // trimmed, 1..200 characters
  owner: string; // email, lowercased; always also in members
  members: string[]; // emails, lowercased, unique, sorted, each in ALLOWED_DOMAIN, at most 50
  archived: boolean;
  createdAt: string;
  updatedAt: string;
}
```

Working documents (`DOC_KINDS`), one per project: `papers` (metadata and include / exclude decisions), `draft`
(the editable plan), `bank` (the pinned Writing Bank snapshot).

Item collections (`ITEM_COLLECTIONS`), many items per project, one object each: `paper-models` (one PaperLab
paper model per paper) and `facts` (the extracted facts of one paper). An item key matches
`^[a-z0-9][a-z0-9-]{0,79}$`; the app uses the paper's hash. Items exist so that one large paper does not have to
fit in a shared document and two members working on different papers never collide.

The Worker does not interpret documents or items; the app parses them with its own Zod schemas.

## Endpoints

| Method | Path                                      | Does                                                                             |
| ------ | ----------------------------------------- | -------------------------------------------------------------------------------- |
| GET    | `/v1/me`                                  | `{ uid, email, name }` of the caller.                                            |
| GET    | `/v1/projects`                            | `{ projects: Project[] }` the caller belongs to, newest `updatedAt` first.       |
| POST   | `/v1/projects`                            | Body `{ title }`. Creates a project owned by the caller. `201` with the Project. |
| GET    | `/v1/projects/:id`                        | The Project.                                                                     |
| PATCH  | `/v1/projects/:id`                        | Body with any of `title`, `archived`, `members`. Returns the Project.            |
| GET    | `/v1/projects/:id/docs/:kind`             | `{ data }` and an `ETag` header. `404` when the document was never saved.        |
| PUT    | `/v1/projects/:id/docs/:kind`             | Body `{ data }`. Saves, returns `{ ok: true }` and the new `ETag`.               |
| GET    | `/v1/projects/:id/items/:collection`      | `{ items: { key, etag }[] }`, sorted by key.                                     |
| GET    | `/v1/projects/:id/items/:collection/:key` | `{ data }` and an `ETag` header.                                                 |
| PUT    | `/v1/projects/:id/items/:collection/:key` | Body `{ data }`. Same rules as a document.                                       |
| GET    | `/v1/projects/:id/plans`                  | `{ versions: { version, frozenAt, frozenBy }[] }`, ascending.                    |
| GET    | `/v1/projects/:id/plans/:version`         | The frozen plan.                                                                 |
| PUT    | `/v1/projects/:id/plans/:version`         | Freezes a plan. `201` with the stored plan.                                      |

Details that are easy to get wrong:

- **PATCH.** Unknown fields are `400`. Only the owner may change `members`; another member gets `403`. The
  owner cannot be removed from `members`. Every member email must be in the allowed domain (`400` otherwise).
  Markers are added for new members and deleted for removed ones.
- **Archived projects** are read-only: `PUT` on docs and plans and `PATCH` of anything but `archived` give `409`.
- **Document and item writes use optimistic concurrency.** The `ETag` is the stored object's R2 `httpEtag`,
  opaque to the client. An update sends `If-Match: <etag>`, exactly as received (one quoted value; a weak, unquoted or
  listed value is `412`), and is written with R2's conditional put (`onlyIf: { etagMatches }`, which takes the
  etag without its quotes), so the comparison and the write are one step; when R2 refuses, the answer is
  `412 precondition_failed`. A first save sends no `If-Match`; a `PUT` without `If-Match` when the object already
  exists is also `412`. `If-Match: *` is not supported. This stops two tabs from silently overwriting each other.
- **Known limit.** Creating an object that must not exist yet (a first save, a frozen plan version) is a read
  followed by a write. Two requests in the same instant could both pass the read. Accepted for a lab-sized app;
  the tests cannot show it.
- **Freezing a plan** (`PUT .../plans/:version`):
  1. `:version` is a positive integer without leading zeros.
  2. The body is parsed with `planSchema` from `src/core/plan/schema.ts`; a failure is `422 plan_invalid` with
     `issues` (path and message of each Zod issue).
  3. `planVersion` must equal `:version` (`400`).
  4. The Worker sets `frozenBy` to the caller's email and `frozenAt` to now, whatever the body said: freezing
     is the signed-in person's action.
  5. `validatePlan` runs on the result; any `blocking` issue is `422 plan_invalid` with `issues` (the
     `PlanIssue` objects). Warnings do not stop the freeze.
  6. The version must be the next one: `1` when the project has no frozen plan, otherwise the highest existing
     version plus one (`409 conflict` otherwise). An existing version is never overwritten (`409`).
  7. The `planId` must equal the `planId` of the project's earlier versions (`409`).
- A frozen plan has no `PATCH` and no `DELETE`. There is no `DELETE` anywhere in v1.

## Tests (names carry the ids)

`worker/src/app.test.ts`, with an in-memory bucket and a fake `verifyToken`:

- `WK-01` 401 without a token, 401 with a bad token, 403 for another domain.
- `WK-02` CORS: an allowed origin is echoed, another origin gets no CORS header, preflight needs no auth.
- `WK-03` create, list (only own projects, newest first), get.
- `WK-04` a non-member gets 404 on every project route.
- `WK-05` PATCH: title and archived by a member; members only by the owner; owner cannot be removed; foreign
  domain refused; markers follow the member list (a removed member no longer lists the project).
- `WK-06` docs and items: unknown kind or collection 404, item list with etags, first save, read with ETag, save with matching If-Match, 412 on a stale or
  missing If-Match, 413 on an oversized body.
- `WK-07` archived project refuses writes with 409 and still allows reads and un-archiving.
- `WK-08` freeze: stored with the caller as `frozenBy` and the Worker's time; listed; readable.
- `WK-09` freeze refusals: schema failure 422, blocking gate issue 422 (with the rule id in `issues`), version
  mismatch 400, existing version 409, skipped version 409, different `planId` 409.
- `WK-10` a plan with only warnings (PP-07, PP-08) freezes.
- `WK-12` an unexpected error is a 500 with CORS headers.
- `WK-11` ids, kinds, collections and item keys from the URL that do not match their pattern never reach the bucket.
